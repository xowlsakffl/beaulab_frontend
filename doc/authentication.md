# Web Authentication

staff/hospital/user 웹은 서버 세션을 사용한다. 인증 토큰과 프로필/권한을 localStorage/sessionStorage에 영속 저장하지 않는다.

- 공통 API client는 동일 출처 `/api/v1/{actor}`를 사용한다. Next rewrite의 서버 전용 `API_URL`이 실제 백엔드를 가리킨다.
- `X-Beaulab-Client: web`, credentials, 변경 요청의 CSRF 헤더는 공통 client가 처리한다.
- CSRF 토큰과 프로필은 메모리에만 보관하며 새 창/새로고침 시 서버에서 복원한다. 복원 요청은 중복 실행하지 않는다.
- 로그인 유지 체크박스는 제거한다. 관리자·병의원 미사용 2시간/최대 24시간, 사용자 웹 미사용 7일/최대 30일은 서버 설정이다. 최대 시간 변경은 다시 로그인한 세션부터 적용된다.
- 사용자 입력 중에는 activity 요청으로 만료 시간을 연장한다. 메뉴 N 배지 polling만으로 로그인 시간이 연장되지는 않는다.
- 로그아웃 API 성공 후 메모리/목록 캐시를 비우고 다른 탭에 로그아웃을 알린다. 네트워크 실패를 로그아웃 성공으로 표시하지 않는다.
- 401은 로그인 해제, 419는 CSRF 만료 오류로 구분한다. 변경 요청은 자동 재시도하지 않는다.
- `CSRF_MISMATCH`는 초대/재설정 링크 만료와 다르다. 이 오류로 링크 만료 페이지에 보내지 않는다.
- 직원 비밀번호 재설정 링크의 최초 검증만 server-only 모듈에서 공개 API에 직접 요청한다. 브라우저 세션이나 쿠키를 서버 간 요청에 전달하지 않는다.
- 인증·개인화 API 응답을 브라우저/Next 캐시에 저장하지 않는다.
- 서버가 실제 계정 유형·활성 상태·권한을 검사한다. 프론트 profile/permission은 UX용이며 인증 증표가 아니다.
- 다운로드도 동일한 세션 client 정책을 사용하며 외부 URL에 인증 헤더를 보내지 않는다.
- API 인증 변경에 앱용 토큰 저장 방식은 포함하지 않는다. 사용자 웹의 기존 채팅 테스트 화면은 개발 전용 `/dev/chat`에서만 제공한다.
