# 중복 실행 방지 요청

충전금 지급·회수·환불·환불 처리 및 문자 발송처럼 중복 실행 시 부작용이 생기는 요청은 `usePersistentIdempotencyKeys`를 사용한다.

1. 요청 payload에서 안정적인 signature를 만든다.
2. `getOrCreate(signature)`로 멱등 키를 가져온다.
3. 네트워크 오류나 모달 닫기만으로 키를 지우지 않는다.
4. 서버 성공 응답을 확인한 경우에만 `confirm(signature)`를 호출한다.

키는 같은 브라우저 탭의 `sessionStorage`에 유지된다. 응답 유실 후 새로고침하거나 모달을 다시 열어도 같은 요청은 동일한 키로 재시도된다. 브라우저가 저장소 접근을 막은 경우에는 현재 페이지 생명주기 동안 메모리 저장소를 사용한다.

병의원 충전금 목록의 지급·회수·안내 발송·환불 요청 상태와 API 조합은 각각 `hooks/hospital-wallet` 아래 전용 hook에서 관리한다. 목록 Client에 금전 요청 구현을 직접 추가하지 않는다.

서버는 멱등 키만 비교하지 않고 병의원, 업무 유형, 금액, 사유 등 핵심 payload도 함께 비교해야 한다. 같은 키가 다른 요청에 사용되면 성공 응답을 재사용하지 않고 오류로 처리한다.
