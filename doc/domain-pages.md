# Staff Web Domain Pages

작성 기준: 2026-07-27

이 문서는 `apps/staff-web` 도메인별 화면 책임을 정리한다.

## 1. 병의원

경로:

- `/hospital-manage/hospitals`
- `/hospital-manage/hospitals/[id]`
- `/hospital-manage/hospitals/[id]/edit`
- `/hospital-manage/hospitals/new`

책임:

- 병의원 목록/summary/상세/등록/수정
- 사업자 정보, 계좌정보, 운영정보
- 로고/이미지 media
- 인증된 계정 정보
- 계정 생성 이메일과 인증된 휴대폰 번호 대상 비밀번호 재설정 링크 전송
- 검수상태, 병의원상태, 운영중지/정상노출
- 관리자 메모, 운영 히스토리
- 미확인 DB 버튼

기준:

- 병의원명은 수정 불가이면 input이 아니라 텍스트로 표시한다.
- 이메일은 실제 사용하는 계정/세금계산서 목적을 구분한다.
- 신규 생성 기본 상태는 정상 운영 기준이다.
- 재설정 링크 전송은 `beaulab.hospital_account_password_reset.send` 권한, 연결된 활성 계정, 인증된 전화번호가 있어야 가능하다. 조건 미충족 시 버튼은 비활성화한다.
- 발송 모달은 전화번호를 조회 표시만 하며 API에는 병의원 ID만 사용한다. 수신자 판단은 서버가 담당한다.
- Hospital Web `/password/reset?token=...`은 이메일 없이 공통 `PasswordResetForm`을 사용한다. 검증 전에는 폼을 노출하지 않으며 만료/폐기는 419, 초기 요청 제한은 429 공통 페이지로 이동한다.
- 링크 검증 응답의 병의원명과 마스킹된 아이디를 폼 제목 아래에 표시한다. 원본 아이디를 프론트에서 받아 가리지 않으며, 계정 확인용 추가 API 요청은 하지 않는다.
- 병의원명은 강조된 제목 아래 문구로 표시하고, 마스킹된 아이디는 새 비밀번호 위의 읽기 전용 공통 입력칸으로 표시한다. 아이디는 수정하거나 제출하지 않는다.
- 재설정 성공 시 완료 문구 아래에 `로그인하러 가기` 버튼을 표시한다. 계정 생성 완료 화면과 동일하게 Hospital Web `/login`으로 연결하며, 로그인 화면 자체는 아직 구현되지 않았다.

## 4.1 충전금

경로:

- `/wallet-manage/deposits`
- `/wallet-manage/hospitals`
- `/wallet-manage/history`

책임:

- 충전금 현황의 연간 입금/사용/환불, 현재 잔액, 월별 추이, 이벤트 DB 부위별 비율, 소진 상위 병의원 조회
- 병의원별 사용 가능한 유상/서비스/전체 잔액 조회
- 서비스 포인트 일괄 지급/회수
- 충전금 안내 문자 발송
- 충전/소진/환불/서비스 적립·회수/전체 내역 탭

기준:

- 차트는 `ui-admin`의 TailAdmin ApexCharts 공통 컴포넌트를 사용하며 도메인 화면은 API 응답을 series로 변환한다.
- 월별 충전금 추이는 현재 월을 포함한 최근 6개월을 TailAdmin `Double Bar Chart` 형태로 표시하고, 카테고리 비율은 `Donut Pie Chart 4` 형태의 공통 파이 차트를 사용한다.
- 전체 현황과 기간별 상위 병의원은 별도 API로 조회해 기간 필터 변경 시 전체 차트를 다시 요청하지 않는다.
- 내역 목록 API는 잔액 변경 원장이 아니라 신청·대기·취소를 포함하는 Operation을 조회한다.
- 기본 탭은 `CHARGE`다.
- 충전 탭에서만 `입금대기/완료/취소` 입금상태 필터를 표시한다.
- `ALL` 탭은 검색어 없이 조회할 때 소진 내역이 제외된다는 서버 정책을 따른다.
- API row를 화면에서 직접 해석하지 않고 `lib/hospital-wallet/history.ts` mapper를 사용한다.
- 탭, 검색어, 기간, 상태, 정렬, 페이지를 URL query에 보존한다.
- 별도 환불 상세 화면이나 상세 조회 API를 두지 않는다.
- `환불신청` 상태는 `beaulab.hospital_wallet.refund_process` 권한이 있는 직원만 클릭할 수 있다.
- 환불상태 변경 팝업은 `환불완료/환불반려`만 선택하며, 환불반려 시 한 줄 반려사유를 필수로 입력한다.
- 환불 신청의 사업자등록증과 통장 사본은 선택 첨부이며, 첨부한 파일에만 확장자와 용량 검증을 적용한다.

## 10. 공지/해시태그/placeholder

공지사항:

- `/notice-manage/notices`
- 목록 필터는 등록일 기간, 채널, 공개여부만 사용한다. 검색 대상은 ID, 제목, 등록한 직원의 이름/아이디다.
- 등록일 기간 필터는 채널/공개여부와 동일한 한 칸 폭을 사용하고, 검색창과 액션 버튼은 하단 한 줄에 배치한다.
- 목록 컬럼은 ID, 등록일, 채널, 제목, 공개여부, 조회수, 관리자 순서다. 관리자는 수정자가 아닌 등록자다.
- 공지사항 등록 버튼은 검색 초기화 오른쪽에 배치하며 `beaulab.notice.create` 권한이 있을 때만 표시한다.
- 목록은 페이지당 15개로 고정하고 개수 선택창을 제공하지 않는다. URL의 `per_page`로 표시 개수를 변경하지 않는다.
- 상세는 왼쪽 `기본 정보` 카드(제목/내용), 오른쪽 `게시 정보` 카드(채널/공개여부/상단공지/첨부파일)와 공통 운영 히스토리 카드로 구성한다.
- 상세 섹션은 `components/notice/detail/NoticeDetailSections.tsx`에서 관리하며 병의원 상세 카드 스타일을 따른다. 카드 `rounded-xl border-gray-200 p-5`, 카드 제목 `text-sm font-bold text-gray-900 mb-5`, 라벨 `pt-0.5 text-xs font-semibold text-gray-500`, 값 `text-sm leading-6 text-gray-800`, 행 간격 `space-y-3`를 사용한다. 제목과 일반 본문에 별도 확대 스타일이나 항목 구분선을 추가하지 않는다.
- 상세 라벨 폭은 병의원 `InfoField`처럼 일반 카드 8.5rem/간격 1rem, 보조 카드 7.25rem/간격 0.75rem로 구분한다. 에디터 본문의 제목·문단 서식은 유지한다.
- 상세 첨부파일은 병의원 사업자등록증 항목처럼 파일명과 작은 outline 다운로드 버튼을 가로로 배치한다. 등록/수정용 파일선택 박스는 상세에서 표시하지 않으며, 첨부파일이 없으면 `-`로 표시한다.
- 등록/수정은 같은 폼 섹션을 사용하며, 상단공지는 공통 체크박스로 표시한다.
- 등록/수정의 각 필드는 이벤트 폼처럼 왼쪽 6rem 라벨과 오른쪽 입력란을 가로로 배치한다. `NoticeFormField`가 라벨/필수 표시/오류 위치를 공유하고, 상단공지 체크박스와 첨부파일도 입력란 시작선을 맞춘다.
- 채널/공개여부 옵션과 표시명은 `lib/notice/options.ts`에서 공유한다. `ACTIVE`는 공개, `INACTIVE`는 비공개다.
- 신규 공지사항의 공개여부 기본값은 비공개(`INACTIVE`)다. 수정 폼에서는 저장된 공개여부를 그대로 불러온다.
- 게시기간, 무기한 게시, 메인 팝업 옵션은 사용하지 않는다. 공개여부는 기존 게시기간과 무관하게 적용한다.
- 첨부파일은 최대 5개, 파일당 20MB이며 공통 파일선택 UI를 사용한다. 원본 파일명은 `file_name`, 다운로드는 API의 `download_path`를 사용한다.
- 등록/수정의 첨부파일 추가 영역은 파일 목록 맨 위에 두고 기존 파일과 새로 선택한 파일을 아래에 표시한다. 최대 개수에 도달하면 추가 영역을 숨긴다.
- 공개여부 변경은 일반 수정 권한과 별개로 `beaulab.notice.status.update` 권한을 확인한다. 등록/수정 폼은 공개/비공개 셀렉트박스를 사용하며, 권한이 없으면 현재 값을 표시한 채 선택을 비활성화한다. 상세/목록은 뱃지를 사용한다.
- 히스토리는 `/notices/{id}/operation-histories`를 별도로 조회하고 페이지네이션 중 기존 내용을 유지한다.
- 병의원 대상 공지사항, FAQ, 1:1문의 placeholder 포함
