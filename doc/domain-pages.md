# Staff Web Domain Pages

작성 기준: 2026-07-27

이 문서는 `apps/staff-web` 도메인별 화면 책임을 정리한다.

## 1. 병의원

경로:

- `/hospital-manage/hospitals`
- `/hospital-manage/hospitals/[id]`
- `/hospital-manage/hospitals/[id]/edit`
- `/hospital-manage/hospitals/new`

책임:

- 병의원 목록/summary/상세/등록/수정
- 사업자 정보, 계좌정보, 운영정보
- 로고/이미지 media
- 인증된 계정 정보
- 계정 생성 이메일과 인증된 휴대폰 번호 대상 비밀번호 재설정 링크 전송
- 검수상태, 병의원상태, 운영중지/정상노출
- 관리자 메모, 운영 히스토리
- 미확인 DB 버튼

기준:

- 병의원명은 수정 불가이면 input이 아니라 텍스트로 표시한다.
- 이메일은 실제 사용하는 계정/세금계산서 목적을 구분한다.
- 신규 생성 기본 상태는 정상 운영 기준이다.
- 재설정 링크 전송은 `beaulab.hospital_account_password_reset.send` 권한, 연결된 활성 계정, 인증된 전화번호가 있어야 가능하다. 조건 미충족 시 버튼은 비활성화한다.
- 발송 모달은 전화번호를 조회 표시만 하며 API에는 병의원 ID만 사용한다. 수신자 판단은 서버가 담당한다.
- Hospital Web `/password/reset?token=...`은 이메일 없이 공통 `PasswordResetForm`을 사용한다. 검증 전에는 폼을 노출하지 않으며 만료/폐기는 419, 초기 요청 제한은 429 공통 페이지로 이동한다.
- 링크 검증 응답의 병의원명과 마스킹된 아이디를 폼 제목 아래에 표시한다. 원본 아이디를 프론트에서 받아 가리지 않으며, 계정 확인용 추가 API 요청은 하지 않는다.
- 병의원명은 강조된 제목 아래 문구로 표시하고, 마스킹된 아이디는 새 비밀번호 위의 읽기 전용 공통 입력칸으로 표시한다. 아이디는 수정하거나 제출하지 않는다.
- 재설정 성공 시 완료 문구 아래에 `로그인하러 가기` 버튼을 표시한다. 계정 생성 완료 화면과 동일하게 Hospital Web `/login`으로 연결하며, 로그인 화면 자체는 아직 구현되지 않았다.

## 4. 이벤트

경로:

- `/ads-manage/events`
- `/ads-manage/events/[id]`
- `/ads-manage/events/[id]/edit`
- `/ads-manage/events/new`

책임:

- 이벤트 목록/summary/상세/등록/수정
- 병의원/의료진/카테고리/옵션 연결
- 검수상태
- 병원 공개여부 `hospital_status`
- 직원 강제중지 `admin_status`
- 이벤트 DB 현황 이동
- 관리자 메모, 운영 히스토리

기준:

- 이벤트 관리의 `status` 단일 상태로 공개여부와 강제중지를 섞지 않는다.
- 성형/쁘띠 카테고리는 최대 3개 선택하고 선택한 항목 중 대표 카테고리 1개를 지정한다.
- 카테고리는 공통 카테고리 selector와 도메인 usage 기준을 따른다.
- 등록/수정의 분류 탭은 성형, 쁘띠, 기획전이며 서로 다른 분류를 섞어 선택하지 않는다.
- 기획전은 `HOSPITAL_EVENT_PROMOTION` usage로 리얼모델, 수능이벤트, 제모, 첫만남 이벤트를 조회한다. 현재는 자식 없는 대분류 4개로 구성하며, 선택 화면은 다른 분류와 동일하게 대·중·소 카테고리 영역을 모두 표시한다.
- 기획전은 1개만 선택하며 다른 항목을 누르면 교체한다. 선택 즉시 대표 카테고리로 지정하고 선택 목록은 숨긴다. 대표 카테고리는 읽기 전용으로 표시한다. 성형/쁘띠는 기존 최대 3개 선택과 대표 지정 방식을 유지한다.
- 카테고리 제목은 각 목록 박스 위에 표시한다. 분류 탭과 이미지/텍스트 등록 전환은 버튼형 `SegmentedTabs`를 사용하며 선택한 버튼을 브랜드색으로 표시한다.
- 이벤트 등록 방식 안내는 `HelpPopover`에 도메인 문구를 전달한다. 의료진 정보노출 선택과 안내 문구는 의료진을 선택한 경우에만 함께 표시한다.
- 텍스트 등록의 우측 이벤트 페이지와 앱 미리보기 모달은 같은 본문 컴포넌트를 사용한다. 시술 대상, 병원 장점, 시술 장점, 전후사진, 의료진, 부작용 안내를 현재 폼 상태로 즉시 반영한다.
- 입력/포커스는 해당 미리보기 영역을 사각 테두리로 표시하되 자동 스크롤하지 않는다. 테두리는 클릭을 가로채지 않는 오버레이로 내용·구분선보다 위에 표시한다. 병원 장점은 포커스 대상에서 제외하고 스크롤바 없이 드래그 가능한 가로 한 줄로 표시한다. 병원 장점과 선택 의료진의 공개용 프로필은 병원/의료진 선택이 바뀔 때만 조회하며 계좌·면허증 등 관리용 정보는 가져오지 않는다.
- 텍스트 미리보기 바깥 카드는 이미지형과 같은 패딩과 제목 위치를 유지하고, 본문 섹션의 중복 패딩은 두지 않는다. 우측 미리보기는 고정 위치·높이 제한·내부 세로 스크롤 없이 내용만큼 늘어난다. 본문 섹션 제목은 앱 미리보기의 이벤트 설명과 같은 `text-sm font-bold text-gray-900` 스타일을 사용하며 섹션 사이는 32px, 제목과 내용 사이는 16px 간격을 둔다. 시술 대상·장점은 내용이 비어 있어도 기본 첫 줄을 유지한다. 전후사진은 등록·수정 업로드와 상세 본문에서 한 줄에 두 세트씩 표시한다. 미리보기(등록·수정 우측, 상세 우측, 모달)는 한 줄에 한 세트로 가로폭 전체를 채우며 전/후 사진은 각각 절반 너비를 사용한다. 라벨은 아래의 상세/등록·수정/미리보기 구분을 따른다.
- 본문 섹션 제목 아래의 구분선은 유지한다. 의료진 프로필 이미지 열은 7rem 너비와 3:4 비율을 사용하며, 사진이 없는 경우에도 같은 크기의 영역을 유지한다.
- 이벤트 등록·수정·복제 폼의 3열 그리드는 상단 정렬(`items-start`)한다. 미리보기 높이가 늘어나도 이벤트 정보 카드와 다른 열은 각자의 내용 높이를 유지한다.
- 병원 장점은 기존 iOS 앱 `HospitalEtcServiceCell.swift`와 Android 앱 `CategoryUtil.kt`의 매핑을 기준으로 원본 이미지를 `public/images/hospital/features`에 그대로 복사해 사용한다. 현재 `수술실명제`는 앱의 `안심실명제`, `사후전담매니저`는 `사후관리` 이미지에 대응시키고 데이터의 항목명은 유지한다. 앱에 대응 이미지가 없는 주차가능은 주차 아이콘, 미등록 코드는 기본 아이콘을 사용한다.
- 병원 장점 목록은 연한 회색 배경에 28px 이미지로 표시하며 5개가 한 번에 보이도록 열 너비를 계산한다. 항목이 5개보다 많으면 다음 항목 24px도 함께 노출한다. 스크롤바는 숨기고 마우스 드래그·터치 스와이프·키보드 스크롤을 유지한다.
- 미리보기 포커스 갱신은 폼의 버블 단계 `onChange`/`onFocus`에서 처리한다. `onInputCapture`의 상태 변경은 controlled 입력의 값을 원복시킬 수 있으므로 사용하지 않으며, 입력 검증은 일괄 값 설정뿐 아니라 연속 키 입력·삭제·실제 select 변경도 확인한다.
- 카테고리 항목은 프론트에 하드코딩하지 않고 백엔드 정의와 selector API를 사용한다. 별도 관리 화면은 추가하지 않는다.
- 가격 옵션은 쁘띠에서만 사용한다. 기획전으로 변경하면 기존 옵션을 제거한다.
- 상담신청단가의 빈칸은 저장 시 기준 단가를 사용하는 기존 동작을 유지한다. 직접 입력한 0은 빈칸과 구분하고, 기준 단가 미만인 값은 입력을 마칠 때 안내 후 기준 단가로 되돌린다. 제출 검증에서도 0을 포함해 기준 단가 미만을 차단하며 요청 생성 과정에서 0을 기본값으로 치환하지 않는다. 백엔드의 공통 저장 처리에서도 기준 단가 미만은 거절한다.
- 텍스트 등록의 시술 장점 아래에 전후사진을 최대 4세트 등록한다. 선택사항이지만 입력한 세트는 전/후 두 장이 모두 있어야 한다. JPG/JPEG/PNG, 장당 5MB이며 비율/픽셀 제한은 없다.
- 전후사진은 기존 미디어와 신규 파일을 함께 유지하며 세트 추가/삭제, 사진 교체, 상세·앱 미리보기를 지원한다. 이미지 등록으로 저장하면 전후사진은 제거한다.
- 이벤트 상세의 가격 아래에는 등록 유형별 정보를 표시한다. 이미지형은 사용 중인 옵션 표(옵션명·회차·정상 가격·이벤트 가격 및 할인율)·부작용안내, 텍스트형은 시술 대상·시술 장점·전후사진·부작용안내 순서다. 빈 항목은 `-`로 표시하고 전후사진은 기존 사진 쌍과 미디어 미리보기 모달을 재사용한다. 우측 미디어 열에 전후사진만 따로 표시하는 카드는 두지 않는다.
- 상세의 가격·이벤트 옵션도 다른 항목과 같은 좌측 라벨/우측 내용 배치를 사용한다. 가격 박스에는 정상 가격·이벤트 가격·상담신청단가와 할인율을 표시하고, VAT 상태는 박스 아래에 읽기 전용으로 표시한다. 옵션 표는 등록·수정과 같은 옵션명·회차·정가·할인가 헤더와 작은 글자·행 간격을 사용하며 할인율을 할인가 옆에 표시한다.
- 상세와 등록·수정의 전후사진은 같은 원형 `전`/`후` 라벨을 공유한다. 사진 좌측 상단에 16px 원형, 흰색 90% 배경, 회색 테두리와 10px 회색 글씨로 표시한다. 인라인·모달 미리보기는 사진 아래 전·후 라벨과 2px 그라데이션 구분선을 유지한다.
- 텍스트형 상세의 우측 썸네일 아래에 공통 `HospitalEventTextPagePreview`를 배치한다. 저장된 상세 값을 기존 폼 mapper로 변환하고, 페이지 Client에서 공통 미리보기 context hook으로 병원 장점과 의료진 공개 정보를 조회해 전달한다. 포커스 값과 폼 입력 이벤트를 연결하지 않으며, 사진 확대와 병원 장점 가로 드래그는 유지한다. 이미지형에서는 기존 이벤트 페이지 이미지를 유지하고 미리보기 context를 조회하지 않는다.
- 읽기 전용 전후사진은 주어진 열 너비와 2:1 세트 비율에 맞춰 줄어든다. 80px 최소 높이는 등록·수정 업로드 영역에만 적용해 좁은 미리보기 열에서 사진이 가로로 넘치지 않게 한다.

## 4.1 충전금

경로:

- `/wallet-manage/deposits`
- `/wallet-manage/hospitals`
- `/wallet-manage/history`

책임:

- 충전금 현황의 연간 입금/사용/환불, 현재 잔액, 월별 추이, 이벤트 DB 부위별 비율, 소진 상위 병의원 조회
- 병의원별 사용 가능한 유상/서비스/전체 잔액 조회
- 서비스 포인트 일괄 지급/회수
- 충전금 안내 문자 발송
- 충전/소진/환불/서비스 적립·회수/전체 내역 탭

기준:

- 차트는 `ui-admin`의 TailAdmin ApexCharts 공통 컴포넌트를 사용하며 도메인 화면은 API 응답을 series로 변환한다.
- 월별 충전금 추이는 현재 월을 포함한 최근 6개월을 TailAdmin `Double Bar Chart` 형태로 표시하고, 카테고리 비율은 `Donut Pie Chart 4` 형태의 공통 파이 차트를 사용한다.
- 전체 현황과 기간별 상위 병의원은 별도 API로 조회해 기간 필터 변경 시 전체 차트를 다시 요청하지 않는다.
- 내역 목록 API는 잔액 변경 원장이 아니라 신청·대기·취소를 포함하는 Operation을 조회한다.
- 기본 탭은 `CHARGE`다.
- 충전 탭에서만 `입금대기/완료/취소` 입금상태 필터를 표시한다.
- `ALL` 탭은 검색어 없이 조회할 때 소진 내역이 제외된다는 서버 정책을 따른다.
- API row를 화면에서 직접 해석하지 않고 `lib/hospital-wallet/history.ts` mapper를 사용한다.
- 탭, 검색어, 기간, 상태, 정렬, 페이지를 URL query에 보존한다.
- 별도 환불 상세 화면이나 상세 조회 API를 두지 않는다.
- `환불신청` 상태는 `beaulab.hospital_wallet.refund_process` 권한이 있는 직원만 클릭할 수 있다.
- 환불상태 변경 팝업은 `환불완료/환불반려`만 선택하며, 환불반려 시 한 줄 반려사유를 필수로 입력한다.
- 환불 신청의 사업자등록증과 통장 사본은 선택 첨부이며, 첨부한 파일에만 확장자와 용량 검증을 적용한다.

## 10. 공지/해시태그/placeholder

공지사항:

- `/notice-manage/notices`
- 목록 필터는 등록일 기간, 채널, 공개여부만 사용한다. 검색 대상은 ID, 제목, 등록한 직원의 이름/아이디다.
- 등록일 기간 필터는 채널/공개여부와 동일한 한 칸 폭을 사용하고, 검색창과 액션 버튼은 하단 한 줄에 배치한다.
- 목록 컬럼은 ID, 등록일, 채널, 제목, 공개여부, 조회수, 관리자 순서다. 관리자는 수정자가 아닌 등록자다.
- 공지사항 등록 버튼은 검색 초기화 오른쪽에 배치하며 `beaulab.notice.create` 권한이 있을 때만 표시한다.
- 목록은 페이지당 15개로 고정하고 개수 선택창을 제공하지 않는다. URL의 `per_page`로 표시 개수를 변경하지 않는다.
- 상세는 왼쪽 `기본 정보` 카드(제목/내용), 오른쪽 `게시 정보` 카드(채널/공개여부/상단공지/첨부파일)와 공통 운영 히스토리 카드로 구성한다.
- 상세 섹션은 `components/notice/detail/NoticeDetailSections.tsx`에서 관리하며 병의원 상세 카드 스타일을 따른다. 카드 `rounded-xl border-gray-200 p-5`, 카드 제목 `text-sm font-bold text-gray-900 mb-5`, 라벨 `pt-0.5 text-xs font-semibold text-gray-500`, 값 `text-sm leading-6 text-gray-800`, 행 간격 `space-y-3`를 사용한다. 제목과 일반 본문에 별도 확대 스타일이나 항목 구분선을 추가하지 않는다.
- 상세 라벨 폭은 병의원 `InfoField`처럼 일반 카드 8.5rem/간격 1rem, 보조 카드 7.25rem/간격 0.75rem로 구분한다. 에디터 본문의 제목·문단 서식은 유지한다.
- 상세 첨부파일은 병의원 사업자등록증 항목처럼 파일명과 작은 outline 다운로드 버튼을 가로로 배치한다. 등록/수정용 파일선택 박스는 상세에서 표시하지 않으며, 첨부파일이 없으면 `-`로 표시한다.
- 등록/수정은 같은 폼 섹션을 사용하며, 상단공지는 공통 체크박스로 표시한다.
- 등록/수정의 각 필드는 이벤트 폼처럼 왼쪽 6rem 라벨과 오른쪽 입력란을 가로로 배치한다. `NoticeFormField`가 라벨/필수 표시/오류 위치를 공유하고, 상단공지 체크박스와 첨부파일도 입력란 시작선을 맞춘다.
- 채널/공개여부 옵션과 표시명은 `lib/notice/options.ts`에서 공유한다. `ACTIVE`는 공개, `INACTIVE`는 비공개다.
- 신규 공지사항의 공개여부 기본값은 비공개(`INACTIVE`)다. 수정 폼에서는 저장된 공개여부를 그대로 불러온다.
- 게시기간, 무기한 게시, 메인 팝업 옵션은 사용하지 않는다. 공개여부는 기존 게시기간과 무관하게 적용한다.
- 첨부파일은 최대 5개, 파일당 20MB이며 공통 파일선택 UI를 사용한다. 원본 파일명은 `file_name`, 다운로드는 API의 `download_path`를 사용한다.
- 등록/수정의 첨부파일 추가 영역은 파일 목록 맨 위에 두고 기존 파일과 새로 선택한 파일을 아래에 표시한다. 최대 개수에 도달하면 추가 영역을 숨긴다.
- 공개여부 변경은 일반 수정 권한과 별개로 `beaulab.notice.status.update` 권한을 확인한다. 등록/수정 폼은 공개/비공개 셀렉트박스를 사용하며, 권한이 없으면 현재 값을 표시한 채 선택을 비활성화한다. 상세/목록은 뱃지를 사용한다.
- 히스토리는 `/notices/{id}/operation-histories`를 별도로 조회하고 페이지네이션 중 기존 내용을 유지한다.
- 병의원 대상 공지사항, FAQ, 1:1문의 placeholder 포함
